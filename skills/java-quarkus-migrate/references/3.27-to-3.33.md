# Quarkus 3.27 → 3.33

Covers wiki Migration-Guide-3.28 to 3.33 (commit `4b6f152`). 3.33 is the LTS continuation of 3.32 and adds no changes of its own.

- Stream: `--stream=3.33`, plugin `3.33.4.1`
- JDK: 17 minimum (unchanged), 25 recommended (3.31 supports Java 25 out of the box)
- Major libraries: Hibernate ORM 7.1 → 7.2, Hibernate Reactive 3.2, Hibernate Search 8.2, JUnit 5 → 6, Testcontainers 2.0, OpenTelemetry SDK 1.49.0, Apicurio Registry 3
- Scan: `scan.sh <root> --framework quarkus --from 3.27 --to 3.33`

## Automated (verify)

`quarkus update` handles these. Check the diff did them.

| Since | Item | Check |
|-------|------|-------|
| 3.31 | Quarkus Maven plugin has `<extensions>true</extensions>` | present in `pom.xml` |
| 3.31 | Surefire/Failsafe `<argLine>` starts with `@{argLine}` so Quarkus can pass Java 25 JVM flags | every custom `<argLine>` keeps `@{argLine}` (for example `@{argLine} -Xmx256m`) |
| 3.31 | JUnit 6: `quarkus-junit5*` → `quarkus-junit*`, `io.quarkus.junit5:junit5-virtual-threads` → `io.quarkus.junit:junit-virtual-threads` (relocations exist) | no `quarkus-junit5` artifact left (`junit5-artifacts`) |
| 3.31 | Testcontainers 2.0 artifact renames | artifacts renamed; package renames in direct Testcontainers use are manual |
| 3.31 | OpenTelemetry package typo fixed: `io.quarkus.opentelemetry.runtime.tracing.intrumentation` → `...instrumentation` | build compiles |

The recipes do not apply OpenRewrite's JUnit 5 → 6 recipes (not open source) and do not switch to the new `quarkus` packaging.

## Manual

### Build and artifacts

| Since | Change | Fix |
|-------|--------|-----|
| 3.30 | Apache Derby support removed: `quarkus-jdbc-derby`, `quarkus-flyway-derby`, `quarkus-hibernate-orm-derby`, `quarkus-devservices-derby` no longer published | Move to another database (`derby`) |
| 3.30 | AOT cache file generation follows JEP 514 and needs Java 25 | Run AOT cache builds on JDK 25 |
| 3.31 | Optional `<packaging>quarkus</packaging>` lifecycle skips `maven-jar-plugin`, install and deploy | Opt in by hand (Migration-Guide-3.31 "New quarkus packaging"); uber-jar users who deploy must add install/deploy plugins |
| 3.31 | lz4-java groupId `org.lz4` → `at.yawk.lz4` | Exclude `org.lz4:lz4-java` pulled by other libraries |
| 3.31 | SmallRye Metrics extension removed | Migrate per the Quarkus Observability Roadmap 2023 blog post (`smallrye-metrics`) |
| 3.31 | `quarkus-test-amazon-lambda` and `LambdaClient` removed | Test Lambdas with RestAssured (AWS Lambda guide) |
| 3.32 | Extension developers: consumed `List<MultiBuildItem>` is immutable; `DevServicesDatasourceProviderBuildItem` constructor changed | Copy before sorting; see PR 52413 for the datasource Dev Services SPI |

### Configuration

| Since | Change | Fix |
|-------|--------|-----|
| 3.28 | `quarkus.http.cors` removed (deprecated since 3.19) | Use `quarkus.http.cors.enabled` (`http-cors-bare`) |
| 3.28 | `key-store`/`trust-store` under `quarkus.smallrye-graphql.client.<name>` removed | Configure TLS in `quarkus.tls` and point the client at it |
| 3.30 | `quarkus.datasource.jdbc.enable-metrics` removed | Use `quarkus.datasource.jdbc.metrics.enabled` |
| 3.31 | `System.getProperty("quarkus.http.port")`, `quarkus.http.test-port` and `test.url` no longer work | Use `ConfigProvider.getConfig().unwrap(SmallRyeConfig.class).getValue(...)` or inject `io.quarkus.vertx.http.HttpServer` |
| 3.31 | `quarkus.https.port` and `quarkus.https.test-port` removed | Use `quarkus.http.ssl-port` and `quarkus.http.test-ssl-port` (`https-port`) |

### Persistence

| Since | Change | Fix |
|-------|--------|-----|
| 3.29 | Injecting a deactivated persistence unit (`quarkus.hibernate-orm.active=false`) fails at startup (`InactiveBeanException`); same for Hibernate Reactive and Hibernate Search beans | Inject `InjectableInstance<Session>` and check `getHandle().getBean().isActive()` |
| 3.29 | Hibernate ORM/Reactive start even with no entities when a datasource is configured | `quarkus.hibernate-orm.enabled=false` (build time) or `quarkus.hibernate-orm.active=false` (runtime) to keep them off |
| 3.29 | Hibernate Search Elasticsearch `max-connections` default 40 (was 20), `max-connections-per-route` 20 (was 10) | Set `quarkus.hibernate-search-[orm\|standalone].elasticsearch.max-connections=20` and `...per-route=10` to keep the old values |
| 3.31 | Hibernate ORM 7.2: changes affect only advanced cases; minimum database versions unchanged | See the ORM 7.2 migration guide |
| 3.31 | JDBC pool default max size 50 (was 20) | Adapt the pool config or the database limit if it relied on 20 |

### Security and TLS

| Since | Change | Fix |
|-------|--------|-----|
| 3.30 | Elytron properties-file realm default hash `sha512` (was `md5`) | Check stored hashes; see Migration-Guide-3.30 "Elytron Security Properties File" |
| 3.31 | TLS registry allows TLS 1.3 only by default | Configure protocols if clients need TLS 1.2 (TLS registry guide, "tls-protocol-versions") |
| 3.31 | Security interceptors run before transaction interceptors | A `@PermissionChecker` that needs a transaction gets its own `@Transactional` |
