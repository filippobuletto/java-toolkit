# Quarkus 2.13 → 3.2

Covers wiki Migration-Guide-2.14 to 3.2 and the Hibernate ORM 5 to 6 guide (commit `4b6f152`). A 2.16 project skips the 2.14–2.16 rows. The 2.17 guide repeats one 3.0 item (keystore password); no 2.17 release line follows 2.16.

- Stream: `--stream=3.2`, plugin `3.2.12.Final`. The project's 2.x plugin cannot run the update: use the 3.2 plugin or a CLI at least that new (quarkus-matrix.md, "Update tooling")
- JDK: 11 minimum (unchanged), 17 recommended
- Major libraries: Jakarta EE 8 → 10 (`javax.*` → `jakarta.*`), Hibernate ORM 5.6 → 6.2, Hibernate Reactive 1 → 2, RESTEasy 4.7 → 6.2, Mockito 5, Maven 3.8.2+ (was 3.6.2)
- Scan: `scan.sh <root> --framework quarkus --from 2.13 --to 3.2` (use `--from 2.16` for a 2.16 project)

## Automated (verify)

Recipes start at 3.0; nothing from 2.14–2.16 is automated. The 3.0 guide lists what `quarkus update` does. No guide heading in this hop carries the `:white_check_mark:` marker.

| Since | Item | Check |
|-------|------|-------|
| 3.0 | Quarkus version bump in the build | BOM and plugin at 3.2.x |
| 3.0 | `javax.*` EE imports → `jakarta.*` (inject, ws.rs, persistence, validation, enterprise, transaction, …) | no `javax-ee` hits; check string literals, reflection and XML descriptors by hand |
| 3.0 | Some dependency coordinates, Quarkiverse extensions bumped to 3.0-compatible versions | dependency tree resolves; no Quarkiverse 2.x artifacts left |
| 3.0 | Renamed configuration properties in config files | no warnings about unknown or deprecated properties at startup |
| 3.0 | `io.quarkus:quarkus-bootstrap-maven-plugin` → `io.quarkus:quarkus-extension-maven-plugin` (extensions only) | plugin artifact renamed |

The recipes do not cover Hibernate ORM 5 → 6 API, query, type or schema changes. Treat everything below as manual.

## Manual

### Hibernate ORM 5.6 → 6.2

Source: Migration-Guide-3.0, "JPA / Hibernate ORM", and the dedicated Hibernate ORM 5 to 6 guide. `quarkus.hibernate-orm.database.orm-compatibility.version = 5.6` is a best-effort switch for the schema and serialization rows marked (compat). It does not cover unsupported databases, and the guide calls it unstable. Plan a real schema migration anyway. Scan signal: `hibernate-orm-6` lists every `org.hibernate` import.

| Since | Change | Fix |
|-------|--------|-----|
| 3.0 | Query hints `javax.persistence.*` are ignored | Use `jakarta.persistence.*` hint names, preferably `org.hibernate.jpa.AvailableHints` constants |
| 3.0 | Legacy Criteria API (`org.hibernate.Criteria`, `Session#createCriteria`) removed | Port to the JPA Criteria API (`legacy-criteria`) |
| 3.0 | Custom type contracts changed (`UserType`, `CompositeUserType`, `@TypeDef`, `@Type`, …) | First try dropping the custom type: ORM 6 maps arrays, enums, UUIDs and time zones natively; force a type with `@JdbcTypeCode(SqlTypes.…)`. Otherwise port it per the ORM 6 user guide |
| 3.0 | HQL: `update from X` disallowed; column names rejected (attribute names only); entity-to-id comparison rejected; collection pseudo-attributes (`.size`, `.elements`, …) removed | `update X …`; use attribute names; compare `e.id = :p`; use `size(c)`, `value(c)`, `index(c)`/`key(c)`, `maxindex(c)`, … |
| 3.0 | Native `count()` returns `Long`, not `BigInteger` | Change the result type |
| 3.0 | Version-specific dialects (`PostgreSQL91Dialect`, …) deprecated; `QuarkusH2Dialect` removed; some dialects moved to `org.hibernate.orm:hibernate-community-dialects` | Remove `quarkus.hibernate-orm.dialect` for supported databases, or use the version-independent class; set `quarkus.datasource.db-version` (`hibernate-dialect`) |
| 3.0 | One sequence per entity hierarchy instead of a shared `hibernate_sequence` (compat) | Run once with `quarkus.hibernate-orm.database.generation=validate` to list missing sequences; create them and set them to `max(id) + 1`; update `import.sql` |
| 3.0 | Sequence increment size defaults to 50, not 1 (compat) | `alter sequence` to the allocation size; hardcode ids in import scripts and restart the sequence after; or set `@SequenceGenerator(allocationSize = 1)` |
| 3.0 | Default id optimizer is `pooled-lo` (ORM and Reactive) | Backwards-compatible; `quarkus.hibernate-orm.id.optimizer.default=pooled` restores `pooled` |
| 3.0 | Enum (without `@Enumerated(STRING)`), `Duration`, `UUID`, `Instant`, `ZonedDateTime`, `OffsetDateTime`, `OffsetTime` map to different SQL types; offset types normalize to UTC (compat, except enum schema validation) | Validate the schema, then `alter table` the columns. If the old normalization zone was not UTC, convert data or set `quarkus.hibernate-orm.mapping.timezone.default-storage=normalize` |
| 3.0 | Some databases and old versions dropped. Quarkus 3.0 minimums: DB2 10.5, Derby 10.14, MariaDB 10.6, SQL Server 2016, MySQL 8, Oracle 12, PostgreSQL 10 | Upgrade the database; MariaDB below 10.3 also needs sequences created |
| 3.0 | `persistence.xml` plus `quarkus.hibernate-orm.*` properties now fails startup | Pick one: `quarkus.hibernate-orm.persistence-xml.ignore=true`, or remove the properties |
| 3.0 | `quarkus.hibernate-orm.globally-quoted-identifiers` deprecated | `quarkus.hibernate-orm.quote-identifiers.strategy=all` |
| 2.15 | IN clause parameter padding on by default | `quarkus.hibernate-orm.query.in-clause-parameter-padding=false` to disable |
| 2.14 | Panache `PanacheRepositoryBase#getEntityManager(Class)` removed | `Panache.getEntityManager(Class)` |
| 2.15 | REST Data with Panache generated resources call `find(query, …)`, not `findAll()` | Overrides of `findAll()`/`findAll(sort)` are no longer called; see the 2.15 guide |
