# Hop 11 → 17

Contents: strong encapsulation · Nashorn removal · Pack200 · CMS · RMI activation · wrapper class constructors · Security Manager deprecation · other changes · verification.

Signals: `deep-reflection`, `illegal-access`, `sun-internal`, `nashorn`, `pack200`, `cms-gc`, `rmi-activation`, `new-wrapper`, `javadoc-old-doclet`, `aggressive-opts`.

## Strong encapsulation — JEP 396 (16), JEP 403 (17)

On 11 illegal reflective access only printed a warning. 16 denies it by default, 17 ignores `--illegal-access`. Symptoms at runtime or in tests:

- `java.lang.reflect.InaccessibleObjectException: Unable to make field private final … accessible: module java.base does not "opens java.lang" to unnamed module`
- Old Lombok, Mockito, Byte Buddy, cglib, Groovy, Kryo, XStream, Hibernate 5, Spring < 5.3 failing during startup.

Fix order:

1. Bump the library (build-blockers.md lists class-file tools). Most fixed this by 2021.
2. Replace own code that reflects into JDK internals: `setAccessible(true)` on JDK classes, reading `String.value`, `Field.modifiers` hacks.
3. Last resort, per package, recorded in progress.md: `--add-opens java.base/java.lang=ALL-UNNAMED` on the JVM and in surefire/test tasks. Also `Add-Opens:` in an executable jar's manifest.

`--illegal-access=permit` in scripts is ignored on 17 (warning) and must be removed.

`setAccessible(true)` on the application's own classes is not affected (same unnamed module).

## Nashorn removed — JEP 372 (15)

`new ScriptEngineManager().getEngineByName("nashorn")` returns `null` on 15+; code then fails with `NullPointerException`.

Options:

1. `org.openjdk.nashorn:nashorn-core:15.x` (standalone, needs 11+; registers under the same `"nashorn"` name). Smallest change.
2. GraalJS (`org.graalvm.polyglot:js` + `polyglot`), via `ScriptEngine` name `"graal.js"` or the Polyglot API.
3. Drop scripting when it only evaluates simple expressions.

Fail loudly when the engine is missing:

<!-- compile: jdk=11 -->
```java
import javax.script.ScriptEngine;
import javax.script.ScriptEngineManager;

static ScriptEngine engine(String name) {
    ScriptEngine engine = new ScriptEngineManager().getEngineByName(name);
    if (engine == null) {
        throw new IllegalStateException("No script engine '" + name + "' on the class path");
    }
    return engine;
}
```

## Pack200 removed — JEP 367 (14)

`java.util.jar.Pack200` and the `pack200`/`unpack200` tools are gone. Ship plain jars (or compressed archives); Apache Commons Compress has a Pack200 implementation for reading old archives.

## CMS removed — JEP 363 (14)

`-XX:+UseConcMarkSweepGC` and `CMS*` flags: JVM prints a warning and ignores them on 14+. Remove; G1 is the default. For low pause targets consider `-XX:+UseZGC` (production from 15) after measuring.

## RMI activation removed — JEP 407 (17)

`java.rmi.activation` is gone; plain RMI remains. Rewrite activatable objects as regular exported objects managed by the application or a service manager.

## Wrapper class constructors — JEP 390 (16)

`new Integer(5)`, `new Long(x)`, `new Boolean(b)`: deprecated for removal, warn at compile time. Synchronizing on wrapper instances warns too (`-XX:DiagnoseSyncOnValueBasedClasses`).

<!-- compile: jdk=8 -->
```java
static Integer boxed(int n) {
    return Integer.valueOf(n);
}

static long parse(String s) {
    return Long.parseLong(s);
}
```

Identity comparisons (`==`) between boxed values were already wrong; `valueOf` caches -128..127 so the change can expose them. Fix with `equals`.

## Security Manager deprecated for removal — JEP 411 (17)

Still works on 17 with a warning. It is permanently disabled on 24 (see 21-to-25.md). Plan the removal now if the code calls `System.setSecurityManager` or installs policy files.

## Other changes

- Old doclet API `com.sun.javadoc` removed (13): port custom doclets to `jdk.javadoc.doclet`.
- `-XX:+AggressiveOpts`, `-XX:+UseParNewGC`: expired, JVM refuses to start. Remove.
- Experimental AOT (`jaotc`) and Graal JIT removed (17): drop `-XX:+UseJVMCICompiler` unless running GraalVM.
- Applet API deprecated for removal (17), removed in 26.
- Always-strict floating point (JEP 306, 17): `strictfp` is redundant; javac warns. Remove the modifier.
- `Socket`/`DatagramSocket` reimplemented (13, 15): legacy `-Djdk.net.usePlainSocketImpl` gone; code relying on old timeout quirks may behave differently.
