## Security Manager permanently disabled — JEP 486 (24)

`System.setSecurityManager(...)` throws `UnsupportedOperationException`; `-Djava.security.manager=allow` or a custom manager class on the command line makes the JVM fail at startup. `System.getSecurityManager()` always returns `null`; `AccessController.doPrivileged` just runs the action.

Fix: delete the code paths. `if (System.getSecurityManager() != null) { … }` blocks are dead; `AccessController.doPrivileged(action)` becomes `action.run()`. Sandboxing needs must move outside the JVM (containers, OS permissions, separate processes).

<!-- compile: jdk=17 -->
```java
import java.util.function.Supplier;

// Before: AccessController.doPrivileged((PrivilegedAction<String>) () -> System.getProperty("user.home"))
static String userHome() {
    return System.getProperty("user.home");
}

static <T> T privileged(Supplier<T> action) {
    return action.get();   // temporary shim while callers are cleaned up
}
```

## sun.misc.Unsafe memory access — JEP 471 (23), JEP 498 (24)

Memory-access methods (`allocateMemory`, `getInt(long)`, `putLong(Object, long, long)`, `objectFieldOffset`, …) are deprecated for removal (compile warnings on 23) and print a runtime warning on first use from 24. `--sun-misc-unsafe-memory-access=allow` silences it temporarily; the plan is `deny` by default and then removal.

Replacements:

- On-heap fields and arrays: `VarHandle`.
- Off-heap memory: FFM `Arena` + `MemorySegment` (final in 22).

Usually the caller is a library (Netty, Kryo, LZ4, old Guava, Hazelcast, Chronicle). Bump it; most current releases switch to VarHandle/FFM on 22+.

<!-- compile: jdk=9 fails-below -->
```java
import java.lang.invoke.MethodHandles;
import java.lang.invoke.VarHandle;

static final class Counter {
    private volatile int value;
    private static final VarHandle VALUE;
    static {
        try {
            VALUE = MethodHandles.lookup().findVarHandle(Counter.class, "value", int.class);
        } catch (ReflectiveOperationException e) {
            throw new ExceptionInInitializerError(e);
        }
    }

    boolean compareAndSet(int expected, int next) {
        return VALUE.compareAndSet(this, expected, next);
    }
}
```

<!-- compile: jdk=22 fails-below -->
```java
import java.lang.foreign.Arena;
import java.lang.foreign.MemorySegment;
import java.lang.foreign.ValueLayout;

static int roundTrip() {
    try (Arena arena = Arena.ofConfined()) {
        MemorySegment segment = arena.allocate(16);
        segment.set(ValueLayout.JAVA_INT, 4, 42);
        return segment.get(ValueLayout.JAVA_INT, 4);
    }   // memory freed here, no finalizer needed
}
```

## JNI restrictions — JEP 472 (24)

Loading native libraries (`System.loadLibrary`, `System.load`) and calling `native` methods print a warning unless native access is enabled for the calling module. FFM restricted methods (`Linker.downcallHandle`, `MemorySegment.reinterpret`) use the same switch.

- Command line: `--enable-native-access=ALL-UNNAMED` (class path) or `--enable-native-access=<module>`.
- Executable jar: manifest attribute `Enable-Native-Access: ALL-UNNAMED`.
- Tests: add the flag to surefire `argLine` / Gradle `jvmArgs`.

`requires jdk.unsupported` has nothing to do with JNI; it only exposes `sun.misc.Unsafe` and `sun.misc.Signal` to named modules.

## Annotation processing not implicit (21 warns, 23 off)

javac no longer runs processors that are only found on the class path. Lombok/MapStruct/AutoValue/Immutables builds fail with "cannot find symbol" for generated code. Fix in the build (java-build: maven.md / gradle.md, `annotationProcessorPaths` or `annotationProcessor` configuration).

## String Templates removed (23)

`STR."Hello \{name}"`, `FMT."…"`, `RAW."…"` compiled only on 21–22 with `--enable-preview`. JEP 465 was withdrawn; on 23+ they do not compile. Rewrite:

<!-- compile: jdk=15 -->
```java
static String greet(String name, int count) {
    return "Hello %s, you have %d messages".formatted(name, count);
}

static String concat(String name) {
    return "Hello " + name;
}
```

For SQL/HTML built with template processors, use `PreparedStatement` parameters or the templating library's escaping; never plain concatenation of untrusted input.

## Structured concurrency rewritten (25, still preview)

`new StructuredTaskScope.ShutdownOnFailure()` / `ShutdownOnSuccess()` were removed in 25 (JEP 505). The 25+ API is `StructuredTaskScope.open()` / `open(Joiner)`, and it changed again in 27 (JEP 533: third type parameter, `join()` throws `ExecutionException`). It is preview on every JDK through 27.

Unless the user opts into preview and pins the JDK, replace it with final APIs: an `ExecutorService` from `Executors.newVirtualThreadPerTaskExecutor()` and `Future`s, cancelling remaining tasks on failure (see `java-modernize/references/concurrency.md`). Remove `--enable-preview` once nothing preview remains.

## ZGC flag — JEP 490 (24)

Non-generational ZGC removed; `-XX:+ZGenerational` and `-XX:-ZGenerational` are obsolete (warning now, startup error once the flag expires). Keep only `-XX:+UseZGC`.

## 32-bit removal — JEP 479 (24 Windows), JEP 503 (25 x86)

No 32-bit x86 builds of JDK 25. Deployments on 32-bit hosts or 32-bit native libraries need 64-bit replacements.

## Other changes

- `java.locale.providers=COMPAT` removed (23): CLDR only. Fix tests that depend on old formats.
- `Thread.suspend/resume` and `ThreadGroup.stop/suspend` are removed (absent in JDK 25); `Thread.stop()` still exists on 25 but throws `UnsupportedOperationException`.
- Virtual threads no longer pin carriers on `synchronized` (JEP 491, 24): `-Djdk.tracePinnedThreads` is gone; remove workarounds that replaced `synchronized` with `ReentrantLock` only for pinning only if the team wants to.
- `jdk.internal`-based tools (old Lombok, old Error Prone) need versions from build-blockers.md.
- XML processing limits lowered (24, JDK-8343022): for example 2500 entity expansions instead of 64000 and 200 attributes per element instead of 10000. Documents that use large DTDs can fail with `JAXP00010001` and similar codes. Raise only the limit that fails, on that factory (`dbf.setAttribute("jdk.xml.entityExpansionLimit", 5000)`) or as a system property; do not disable limits.
- XSLT extension functions are off by default (25): stylesheets calling Java (`xalan://`, `http://xml.apache.org/xalan/java/…`) fail with "Use of the extension function … is not allowed". Prefer rewriting the stylesheet or passing values as parameters; `jdk.xml.enableExtensionFunctions=true` re-enables them for trusted stylesheets only (java-secure-coding, injection.md).
