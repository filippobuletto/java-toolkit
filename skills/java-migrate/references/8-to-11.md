Contents: Java EE and CORBA removal · JavaFX · internal APIs · version string · rt.jar / tools.jar · GC logging and flags · other removals · verification.

Signals: `jaxb`, `jaxws`, `javax-activation`, `javax-annotation-ee`, `javax-transaction-ee`, `corba`, `javafx`, `sun-internal`, `sun-misc-base64`, `tools-jar`, `java-version-parse`, `gc-log-flags`, `permgen-flags`.

## Java EE and CORBA modules removed — JEP 320 (11)

Compile error: `package javax.xml.bind does not exist` (or `javax.annotation.PostConstruct`, `javax.xml.ws`, …).

Add the standalone artifacts. Two choices, decide once for the whole project:

- **Keep the `javax.*` namespace** (smallest change, no source edits): last `javax` releases.
- **Move to `jakarta.*`** (needed later for Jakarta EE 9+ frameworks such as Spring Boot 3): source edits in imports. That is a framework-level migration; record it as a prerequisite unless the user asked for it.

| Removed module | javax namespace (no source change) | jakarta namespace |
|----------------|------------------------------------|-------------------|
| `java.xml.bind` (JAXB) | `javax.xml.bind:jaxb-api:2.3.1` + `org.glassfish.jaxb:jaxb-runtime:2.3.x` | `jakarta.xml.bind:jakarta.xml.bind-api:4.x` + `org.glassfish.jaxb:jaxb-runtime:4.x` |
| `java.xml.ws` (JAX-WS, SAAJ, `javax.jws`) | `javax.xml.ws:jaxws-api:2.3.1` + `com.sun.xml.ws:jaxws-rt:2.3.x` | `jakarta.xml.ws:jakarta.xml.ws-api:4.x` + `com.sun.xml.ws:jaxws-rt:4.x` |
| `java.activation` (JAF) | `javax.activation:javax.activation-api:1.2.0` | `jakarta.activation:jakarta.activation-api:2.x` |
| `java.xml.ws.annotation` (`@PostConstruct`, `@PreDestroy`, `@Resource`, `@Generated`) | `javax.annotation:javax.annotation-api:1.3.2` | `jakarta.annotation:jakarta.annotation-api:2.x/3.x` |
| `java.transaction` (JTA classes; `javax.transaction.xa` stays in JDK) | `javax.transaction:javax.transaction-api:1.3` | `jakarta.transaction:jakarta.transaction-api:2.x` |
| `java.corba`, `javax.rmi.CORBA`, `javax.activity` | `org.glassfish.corba:glassfish-corba-orb` (best effort) | — |

Notes:

- `jakarta.xml.bind-api` **2.3.x** still uses the `javax.xml.bind` package; 3.0+ uses `jakarta.xml.bind`. Check the package, not the artifact name.
- Pin versions via the framework BOM when one manages them (Spring Boot, Quarkus); do not override BOM-managed versions.
- `xjc`/`wsimport` tools are gone from the JDK: use `org.codehaus.mojo:jaxb2-maven-plugin` / `jaxws-maven-plugin` (or the Gradle equivalents).
- `@Generated` used by annotation processors: from 9 prefer `javax.annotation.processing.Generated` (JDK-owned).

## JavaFX (11)

Unbundled from Oracle JDK; never in most OpenJDK builds. Add `org.openjfx:javafx-controls` (and modules used) plus `org.openjfx:javafx-maven-plugin` or the `org.openjfx.javafxplugin` Gradle plugin. Same JavaFX major as the JDK is the safe choice.

## JDK internal APIs (9; enforced at compile time with `--release`)

`--release 9+` hides non-exported packages, so code importing `sun.*` / `com.sun.*` internals fails to compile. Run `jdeps --jdk-internals` for the official replacement list.

| Internal | Replacement |
|----------|-------------|
| `sun.misc.BASE64Encoder/Decoder` (removed) | `java.util.Base64` |
| `sun.reflect.Reflection.getCallerClass` | `StackWalker.getInstance(RETAIN_CLASS_REFERENCE).getCallerClass()` |
| `sun.misc.Cleaner` | `java.lang.ref.Cleaner` (9) |
| `sun.security.x509.*` (generating certs) | Bouncy Castle |
| `com.sun.image.codec.jpeg` | `javax.imageio.ImageIO` |
| `sun.misc.Unsafe` | Still accessible via `jdk.unsupported`; plan the 21-to-25 migration |

<!-- compile: jdk=8 -->
```java
import java.nio.charset.StandardCharsets;
import java.util.Base64;

static String encode(String text) {
    return Base64.getEncoder().encodeToString(text.getBytes(StandardCharsets.UTF_8));
}

static String decode(String base64) {
    return new String(Base64.getDecoder().decode(base64), StandardCharsets.UTF_8);
}
```

<!-- compile: jdk=9 fails-below -->
```java
static Class<?> caller() {
    return StackWalker.getInstance(StackWalker.Option.RETAIN_CLASS_REFERENCE).getCallerClass();
}
```

## Version string — JEP 223 (9)

`java.version` is `11.0.24`, `17`, `21.0.5`; the `1.` prefix is gone. Code doing `split("\\.")[1]` or `startsWith("1.8")` breaks.

<!-- compile: jdk=10 fails-below -->
```java
static int feature() {
    return Runtime.version().feature();
}
```

`Runtime.version().feature()` is 10+; on 9 use `Runtime.version().major()` (deprecated later).

## rt.jar, tools.jar, extension and endorsed dirs — JEP 220 (9)

- Build scripts referencing `${java.home}/lib/rt.jar` or `tools.jar`: remove. Compiler API through `javax.tools.ToolProvider.getSystemJavaCompiler()`.
- Class loading from `jrt:/` instead of `rt.jar` paths.
- `-Djava.ext.dirs`, `-Djava.endorsed.dirs`: removed; put jars on the class path.
- `ClassLoader.getSystemClassLoader()` is no longer a `URLClassLoader`; casting it fails at runtime. Code that adds URLs to it needs a new `URLClassLoader` or an agent.

## GC logging and flags — JEP 158/271 (9)

| Old | New |
|-----|-----|
| `-XX:+PrintGCDetails -XX:+PrintGCDateStamps -Xloggc:gc.log` | `-Xlog:gc*:file=gc.log:time,uptime,level,tags` |
| `-XX:+UseGCLogFileRotation -XX:NumberOfGCLogFiles=5 -XX:GCLogFileSize=10M` | `-Xlog:gc*:file=gc.log:time,uptime:filecount=5,filesize=10m` |
| `-XX:+PrintTenuringDistribution` | `-Xlog:gc+age=trace` |
| `-XX:MaxPermSize`, `-XX:PermSize` | drop (Metaspace since 8) |

Several old flags make JDK 9+ refuse to start ("Unrecognized VM option"). Check every launch script, Dockerfile, `JAVA_OPTS`/`JAVA_TOOL_OPTIONS`, Helm values, and surefire `argLine`.

G1 is the default GC from 9 (was Parallel). Throughput-tuned services may need `-XX:+UseParallelGC` explicitly; measure before deciding.

## Other changes

- `Thread.destroy()`, `Thread.stop(Throwable)`, `Runtime.runFinalizersOnExit` removed (11).
- `javah` removed (10): use `javac -h <dir>`.
- `java.awt.peer`, `sun.awt` internals hidden.
- Default `Locale` data: CLDR is the default provider (9). Date/number formatting can change (for example German short month names with a dot). Tests asserting formatted dates may fail; fix with an explicit pattern, or `-Djava.locale.providers=COMPAT,CLDR` as a temporary measure (COMPAT removed in 23).
- `Class.newInstance()` deprecated (9): `getDeclaredConstructor().newInstance()`.
